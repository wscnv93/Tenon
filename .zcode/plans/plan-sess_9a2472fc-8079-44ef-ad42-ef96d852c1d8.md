# Tenon — 基于 pi 的 Codex 风格桌面客户端:可行性结论 + 实施计划

(脚手架创建在当前工作区目录,所有包名/产品名使用 `tenon`,如 `@tenon/desktop`、`tenon-codegraph` 等)

## 一、可行性结论:高度可行

| 需求 | 依据 |
|---|---|
| 基于"最新的 pi" | pi 已更名 `earendil-works/pi`(v0.85.x, MIT),官方提供 **RPC 模式**(`pi --mode rpc`,明确为"嵌入 IDE/App/自定义 UI"设计):流式事件、`get_available_models`、审批对话子协议、会话树操作(fork/clone/switch) |
| 各厂商模型+key 配置+自动拉取 | pi-ai 原生支持 30+ 厂商(OpenAI/Anthropic/Google/DeepSeek/ZAI/OpenRouter/Kimi/MiniMax/Qwen/Groq/xAI/Ollama 及任意 OpenAI 兼容端点);模型目录源自 models.dev,运行时自动刷新(4h 节流+离线缓存);key 走 `auth.json`/环境变量/OAuth |
| 内置 codegraph | pi 官方有 pi-tree-sitter(WASM)先例;MIT 参考 CodeGraphContext(实测减少 ~70% 工具调用);方案:web-tree-sitter 进程内增量索引 + SQLite(FTS5+边表) |
| 沙箱 | `@anthropic-ai/sandbox-runtime`(Apache-2.0, TS)= Claude Code 沙箱底层,macOS Seatbelt + Linux bubblewrap,Codex 式三档模式可直接复刻 |
| 三栏+流式界面 | 官方 Codex app 本身是 Electron+子进程协议架构,布局/交互有官方文档与截图可依;opencode 的流式 markdown 方案(marked+remend+@shikijs/stream+worker 解析)是成熟开源参考 |
| deepseek harness 式轨迹、一切可回溯 | pi 会话即树形 JSONL(id/parentId),每条消息含 usage/成本/耗时,官方支持 fork/重放;DeepSeek dsh 的 `ui-trajectory` 包提供时间轴+检查器 UI 范式 |

主要风险:pi 仍在 0.x 快速演进(接口有破坏性变更先例)、Seatbelt 被 Apple 标记 deprecated(社区通用做法,可后续加 Docker 档位兜底)。均已有对策(见风险节)。

## 二、总体架构

```
Electron Renderer (React + TS)
 ├─ 左栏:项目/会话树(分支树)
 ├─ 中栏:对话流(流式 markdown/思考块/工具块) + Composer(模型/推理档位/执行模式)
 └─ 右栏 Tabs:检视 diff | 文件树 | 轨迹回放
Electron Main (Node 22)
 ├─ PiHost:spawn pi 二进制 --mode rpc(stdio JSONL,每项目一进程,会话内 switch/fork)
 ├─ SandboxManager:@anthropic-ai/sandbox-runtime 三档沙箱 + 审批升级
 ├─ CodegraphService:索引 worker(独立进程)+ SQLite
 ├─ GitService:simple-git(diff/stage/revert/hunk 级操作)
 └─ TrajectoryService:解析 pi 会话 JSONL → 轨迹视图模型
pi 进程内扩展(随 app 分发到私有 agentDir)
 ├─ tenon-codegraph / tenon-sandbox(工具包装+审批 ui 请求) / tenon-review(自测检视工作流)
```

要点:UI 与引擎完全进程隔离(UI 崩溃不杀 agent);扩展机制让我们不改 pi 源码即可注入工具。

## 三、pi 版本与更新策略(已确认)

- pi 以**独立二进制 sidecar** 打进 app 安装包,**版本锁定在 lockfile**,仅随 Tenon app 发版一起更新(app 用 electron-updater 自动更新);不做 pi 独立自动更新。
- 理由:pi 0.x 接口有破坏性变更先例,强绑定保证 protocol 适配层与扩展始终和引擎同版本经过整体测试。
- 设置中保留一个高级项:允许指向系统 PATH 里的 pi(便于开发调试),默认关闭。

## 四、仓库结构(pnpm monorepo)

```
tenon/
├─ apps/desktop/            # electron-vite: src/main, src/preload, src/renderer
├─ packages/protocol/       # pi RPC 事件/命令的类型化封装 + 主↔渲染 IPC 契约(TypeBox)
├─ packages/pi-extensions/  # tenon-codegraph / tenon-sandbox / tenon-review
├─ packages/codegraph-core/ # tree-sitter WASM 增量索引 + SQLite(symbols/FTS5/edges)
├─ packages/trajectory/     # 会话 JSONL → 轨迹模型(turns/steps/usage/timing/分支)
└─ packages/ui/             # 流式 Markdown、diff 卡片、工具块、时间轴、审批卡组件库
```

## 五、界面复刻规格(Codex 骨架+融合)

- **左栏**:项目列表(每 codebase 一项)→ 会话/任务树(pi 树形会话直接映射,可从任意节点分叉);"新线程"按钮;底部账号/设置。
- **中栏**:线程模式 tabs(Local/Worktree)+ 分支选择;消息流=用户消息 / assistant 流式 markdown / 可折叠思考块(实时耗时)/ 工具调用单行灰条(点击展开命令·输出·diff);Composer=模型选择器(厂商分组·搜索·key 状态标注)+ 推理档位 + 执行模式(Shift+Tab 循环:只读/确认改/自动改/完全访问)+ @文件 + 斜杠命令。
- **右栏 Tabs**:
  - **检视**:unified diff 按文件折叠卡片(±N 计数)、范围选择(未提交/本分支/首轮)、整体/文件/hunk 级暂存与回退、行内评论(可一键回灌给 agent)、/review 结果内联渲染;
  - **文件树**:git 变更过滤、预览、拖入对话;
  - **轨迹**:dsh 风格——时间轴(拖选缩放)+ 事件表(虚拟滚动)+ 步进检查器(每步 tokens/耗时/输入输出/附件/沙箱与审批事件);任意历史会话可加载,任意节点可 fork 续跑。
- **内置终端**:node-pty + xterm.js,Cmd⌥J 切换(M5)。

## 六、关键子系统设计

1. **模型/厂商管理**:设置页厂商卡片+自定义 OpenAI 兼容端点(baseUrl+key);key 由主进程写入 pi `auth.json`(沿用 pi 优先级与 `$VAR`/`!shell 命令` 能力);OAuth 订阅登录复用 pi 流程;模型列表走 RPC `get_available_models`+自动刷新。
2. **沙箱与审批**:三档 read-only / workspace-write / full(写入 srt 动态 profile:可写=工作区+tmp,默认断网);tenon-sandbox 扩展拦截 bash/edit/write → 经 extension ui 子协议弹原生审批卡(命令+diff+原因;允许一次/本会话/总是/拒绝);沙箱内失败→审批后沙箱外重跑(Codex 式);allow/ask/deny 规则层(项目覆盖用户)。
3. **codegraph**:web-tree-sitter + tree-sitter-wasms 预编译语法,file-watch 增量索引,SQLite 存 symbols/FTS/调用·引用·继承边;首批语言 ts/tsx/js/py/go/rs;暴露工具 `explore_symbol`/`get_callers`/`get_callees`/`search_code`(紧凑输出省 token);索引进度在 UI 显示,未覆盖语言回退 FTS。
4. **研发自测+检视一体化**(tenon-review 扩展):`run_tests` 沙箱内自动探测并跑测试框架(vitest/jest/pytest/go test…),失败结构化回灌 agent 循环修复;`self_review` 对本轮 diff 按清单自检;行内评论"发送给 agent"生成 followUp;一键流水:实现→自测→修复→检视摘要(改动/测试结果/风险)。
5. **轨迹回放**:trajectory 包解析树形 JSONL(usage/耗时内建)+ 扩展以 custom entries 附挂沙箱/审批/索引事件;回放=时间轴+事件表+检查器,支持历史加载与节点 fork。

## 七、里程碑(单人全职粗估)

- **M0 骨架(1–2 周)**:脚手架 + pi 二进制 sidecar(锁定版本)+ RPC 客户端 + 中栏流式对话 + 模型选择器/API key 配置 + 会话持久化恢复。验收:配任意厂商 key→自动出模型→流式对话→重启可续。
- **M1 三栏+检视(1–2 周)**:左栏项目/会话树、右栏检视 tab(diff/暂存/回退/hunk)、工具块与 diff 卡片渲染、Composer 执行模式。
- **M2 沙箱+审批(1 周)**:srt 集成、三档模式、审批卡、规则层。
- **M3 codegraph(1–2 周)**:索引器+扩展工具+索引 UI,5 语言。
- **M4 轨迹(1–2 周)**:trajectory 解析、右栏轨迹 tab(时间轴+检查器)、分支导航+fork。
- **M5 一体化收尾(1–2 周)**:run_tests/self_review/行内评论回灌/检视摘要;内置终端;electron-updater 自动更新(pi 随发版换新)。

## 八、关键依赖

`@earendil-works/pi-coding-agent`(≥0.85,精确锁版,仅随 app 发版升级)、`@anthropic-ai/sandbox-runtime`、`web-tree-sitter`+`tree-sitter-wasms`、`better-sqlite3`、`simple-git`、`node-pty`+`xterm.js`、`marked`+`remend`+`@shikijs/stream`、`TanStack Virtual/Table`、`electron-vite`+`electron-builder`、jotai、TypeBox。

## 九、风险与对策

1. **pi 0.x 接口漂移**:锁精确版本、与 app 发版强绑定(已确认策略);`packages/protocol` 做唯一适配层;升级 pi 时跑协议兼容冒烟测试;跟踪 pi-server/chord 演进,必要时迁移。
2. **扩展随 app 分发的加载方式**(agentDir/配置)需 M0 实测验证;备选:app 私有 agentDir 内 npm 安装我们的扩展包。
3. **Seatbelt deprecated**:短期社区通用做法;预留 Docker 高隔离档位(设置项,后期)。
4. **流式渲染性能**:markdown worker 解析+块投影(opencode 方案)+虚拟滚动。
5. **codegraph 语法覆盖**:5 语言先行,FTS 兜底,大仓增量索引。
6. **复刻边界**:复刻布局与交互,不使用 Codex/ZCode 名称与 logo。
